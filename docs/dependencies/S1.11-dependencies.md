## Runtime-pin correction (Step 2 discovery)

The Step 1 pair (5.1.12, 8.3) is unresolvable: elgg 5.1.12 exact-pins
laminas/laminas-mime 2.11.0, whose `~8.0.0 || ~8.1.0 || ~8.2.0` constraint
excludes 8.3 (resolver output, update log). The platform pin was corrected
to 8.2 — the highest line the pinned tree supports;
`coldtrick/elgg_webserver:8.2` exists upstream (tag listing,
`.log/coldtrick-tags.json`). The PHP 8.3 runtime arrives with the Elgg 7.1.0
target (Story S1.13, per `docs/tech_stack.md`). `--ignore-platform-req=php`
was rejected: it would install a dependency tree that declares it does not
support the runtime, on a production upgrade path.

## Install status

The run resolved and wrote the lock, then failed mid-install: the
asset-packagist npm-asset tarballs (npm-asset/jquery,
npm-asset/yaireo--tagify) cannot be extracted on the still-7.4 runtime —
Composer 2.10 refuses to parse tar archives on PHP < 8.0 (`Platform.php`
line 131). The elgg core itself extracted cleanly
(`vendor/elgg/elgg/composer.json` reports 5.1.12). The partial extraction
(zip dists applied, tar dists not, the three removals applied) leaves the
4.3.10-era autoload map referencing the removed `symfony/polyfill-php81` —
the guard suite fatals at bootstrap (`Failed opening required
.../symfony/polyfill-php81/bootstrap.php`, `autoload_real.php` line 41) and
is unrunnable until the sync completes. Completing the sync on the 7.4
runtime (e.g. the CI workflow's `COMPOSER_ALLOW_UNSAFE_PHAR_METADATA`
override) would not restore the suite either: the resolved 5.x tree requires
PHP 8.x at runtime (laminas-mail 2.25.1 `~8.1.0 || ~8.2.0 || ~8.3.0`;
laminas-servicemanager/stdlib/validator `~8.2.0 || ~8.3.0 || ~8.4.0 ||
~8.5.0`; doctrine/event-manager `^8.1`). The vendor-tree sync and the
install-from-lock verification therefore complete after the Story S1.11
Step 3 image rebuild (PHP 8.2), which unblocks tar extraction and hosts the
suite.

### Sync completion (Story S1.11 Step 3, 2026-11-17)

The sync completed in the rebuilt PHP 8.2.21 container: `composer update
--lock` refreshed the lock's content-hash and `platform-overrides.php` to
8.2.21, and `composer install` reported "Installing dependencies from lock
file (including require-dev)" — the asset-packagist tar dists
(npm-asset/jquery, npm-asset/yaireo--tagify) extracted natively on the 8.2
runtime, closing the partial-install state above. The vendored core reports
5.1.12 (`vendor/elgg/elgg/composer.json`), and the guard suite is green
(138 tests, 1158 assertions) with the pin guards updated to the new pair.
