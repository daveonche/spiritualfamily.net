## Other Relevant Dependencies

- `composer.lock` and the tracked `src/vendor/` regenerate in the same `composer update` run that installs 9.6.38 (S1.9 Step 1 resume)
- Composer source configuration: `src/composer.json` gains a `repositories` entry for `https://asset-packagist.org` — elgg 3.3.25's own requires include `bower-asset/*` and `npm-asset/*` packages (resolver evidence: `bower-asset/fontawesome ~5.6 -> could not be found in any version`) that are not published on Packagist; the repository is the delivery mechanism for the approved elgg pin's transitive requirements, not a new package dependency
- roave/security-advisories pinned to commit `69ddaead6caa68f4f6190e2ee732f103326e78ba` (2026-10-01) via the root require `dev-master#<sha>` — elgg 3.3.25 requires this package at floating `dev-master`, and the current `dev-master` conflicts with every PHP version below 8.2.35 (resolver evidence: `roave/security-advisories dev-master conflicts with php <8.2.35|>=8.3,<8.3.36|>=8.4,<8.4.27|>=8.5,<8.5.12`), which the pinned 7.4.27 platform cannot satisfy; the commit pin selects the newest probed conflict-free commit (GitHub probes from 2024-01-01 through 2026-10-01 all show no `php` conflict entry; the policy landed between 2026-10-01 and the 2026-10-30 resolver run). Trade-off: the advisory conflict list freezes at the pinned commit — stale coverage, conflict metadata only, no runtime code. Solver limitation (fourth update run): the `#sha` pin fixes the installed code, but the resolver reads the package's solving metadata from Packagist's `dev-master` branch head, whose `php` conflict still blocks resolution — so `composer update` must run with `--ignore-platform-req=php` until the runtime pin reaches ≥ 8.3.36 (the flag removes the php platform package from the solver pool for that run only; the real 7.4.27 platform is unchanged, and elgg's `php >=7.2` / phpunit's `php >=7.3` are verified against it). `composer install` from the lock is unaffected — it does not re-solve and does not evaluate conflicts, so CI and fresh checkouts need no flag; `composer check-platform-reqs` after the flagged update verifies no transitive package was picked with a php requirement above 7.4. Revisit at S1.13: the PHP 8.3 pin must be ≥ 8.3.36 for a floating `dev-master` to resolve without the flag
