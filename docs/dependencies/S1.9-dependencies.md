## Core Framework/Runtime Dependencies

- elgg/elgg 3.3.25 (require — the S1.9 upgrade target, pinned in Step 1)
- PHP runtime 7.4.27 (`config.platform.php`; elgg 3.3.25 declares `php >=7.2`, so the runtime pin does not move)
- elgg/login_as 2.1.0 (replace — tracks the version bundled with elgg 3.3.25; drafted fix from 1.9.2, applied together with this report's change)

## Story-Specific Dependencies

- phpunit/phpunit 9.6.38 (require-dev, replacing 4.8.36)
  - Reason: 4.8.36 is blocked by security advisory `PKSA-z3gr-8qht-p93v` (Composer advisory blocking refused to load it, failing the S1.9 Step 1 `composer update`); 9.6.38 is the highest stable line running on the pinned PHP 7.4.27 (requirement card: `php >=7.3`)
  - Consequence: the guard suite (~30 classes in `src/tests/`) migrates off the PHPUnit 4 API (`\PHPUnit_Framework_TestCase` → `\PHPUnit\Framework\TestCase`, `void` `setUp()`/`tearDown()` signatures) as Phase 4A implementation work after this approval

## Other Relevant Dependencies

- `composer.lock` and the tracked `src/vendor/` regenerate in the same `composer update` run that installs 9.6.38 (S1.9 Step 1 resume)
- Composer source configuration: `src/composer.json` gains a `repositories` entry for `https://asset-packagist.org` — elgg 3.3.25's own requires include `bower-asset/*` and `npm-asset/*` packages (resolver evidence: `bower-asset/fontawesome ~5.6 -> could not be found in any version`) that are not published on Packagist; the repository is the delivery mechanism for the approved elgg pin's transitive requirements, not a new package dependency
- roave/security-advisories provided via the root `replace` (`"roave/security-advisories": "dev-master"`) — elgg 3.3.25 requires this package at floating `dev-master`, but its advisory-conflict list is incompatible with elgg 3's own dependency tree: it conflicts with every PHP version below 8.2.35 (third update run: `roave/security-advisories dev-master conflicts with php <8.2.35|>=8.3,<8.3.36|>=8.4,<8.4.27|>=8.5,<8.5.12`, blocking the pinned 7.4.27 platform) and, once that was bypassed with `--ignore-platform-req=php`, with `symfony/http-foundation 3.4.x-dev` (fifth update run) — the EOL Symfony 3.4 line elgg 3.3.25 itself requires (`~3.4`). Roave conflicting with EOL lines is its designed behavior, and no Composer flag bypasses a package-vs-package conflict, so elgg 3 + roave is unresolvable by any pin or flag: the `#sha` commit-pin attempt (commit `69ddaead6caa68f4f6190e2ee732f103326e78ba`, 2026-10-01, the newest probed commit without a `php` conflict entry) failed because the resolver reads the package's solving metadata from Packagist's `dev-master` branch head, and the symfony conflict stands there. The root `replace` satisfies elgg's require without installing the package, keeping its conflict metadata out of the solver entirely (same mechanism as the `elgg/login_as` replace; the declared version must satisfy the requiring constraint, hence exactly `dev-master`). Trade-off: the advisory-conflict security layer is dropped — it was already frozen-stale under the commit pin and non-functional against the pinned runtime; roave is conflict metadata with no runtime code, so elgg's runtime is unaffected. `composer update` no longer needs `--ignore-platform-req=php` (roave was the only php-conflict source in the solve); `composer check-platform-reqs` after the update verifies the lock installs on the real 7.4.27 platform
- No peer dependencies; no collision with elgg 3.3.25's requires (evidence: requirement card cited in the Step 3 analysis)

All versions are locked and verified compatible.
