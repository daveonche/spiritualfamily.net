Dependency-management record for the fourth sequential upgrade hop
(Elgg 5.1.12 → 6.3.10, Story S1.12), following the S1.11 precedent
(`docs/dependencies/S1.11-dependencies.md`).

| Package | Previous pin | New pin | Declared in |

| elgg/elgg | 5.1.12 | 6.3.10 | `src/composer.json` require; `src/composer.lock` regenerated 2026-11-19 by `composer update` inside the dev-stack app container against `config.platform.php 8.2.21`, vendor tree synced in the same run |

## New platform requirement: ext-intl

elgg/elgg 6.3.10 requires `ext-intl *` (`composer show -a elgg/elgg
6.3.10`); its full extension set is `ext-intl`, `ext-json`, `ext-gd`,
`ext-pdo`, `ext-xml`, `ext-mbstring`. The first `composer update` (38m8s
wall) aborted in the resolution phase — "Problem 1: elgg/elgg 6.3.10
requires ext-intl * -> it is missing from your system" — before any lock or
vendor write: the app image ships `intl.so` in extension_dir but the repo's
overwriting `docker/app/php/extensions.ini` never loaded it (same cause as
pdo_mysql/gd/zip in earlier hops). The resolver reported only ext-intl as
missing, so the remaining requirements were already satisfied by the PHP
8.2.21 runtime; the 5.1.12 tree never required intl, which is why the image
had passed every platform check until this hop.

Remediation (commit `41ffabc`): `extension=intl` added to
`docker/app/php/extensions.ini`; app image rebuilt with an explicit
`PHP_VERSION=8.2` (the S1.11 stale-env gotcha); the recreated container
reports PHP 8.2.21 with intl loaded (`php -m`). The runtime version pin does
not move. The re-run completed: lock regenerated, vendor tree synced, guard
suite green (138 tests, 1268 assertions).

CI twin remediation (commit `32114a6`): the same platform requirement
failed CI's `composer-install` job on the next push — that job's
extension-prep step installed only gd on the official `php:8.2.21-cli`
image, whose CLI runtime ships no intl (the 5.1.12 lock never required it,
so the step's comment still recorded the pre-6.3.10 requirement set). The
step now installs `libicu-dev` through the same pinned snapshot.debian.org
apt and compiles `gd intl` via `docker-php-ext-install`, asserting both
extensions load; platform checks stay enforced (no
`--ignore-platform-reqs` anywhere).

## Upstream abandonment notices (observed in the update log; no action)

Composer flagged five packages in the pinned core's tree as abandoned during
the update: `eloquent/composer-config-reader`, `eloquent/enumeration`,
`laminas/laminas-loader`, `laminas/laminas-mail` (suggests symfony/mailer),
`laminas/laminas-mime` (suggests symfony/mime). For the two laminas packages
the suggested replacements are core-tree swaps, not app-level changes; no
action is taken this hop. Recorded for awareness at the S1.13 final hop.
